# Telegram-бот «Возврат переплаты по кредитам»

Юридико-финансовый Telegram-бот: воронка подписка → инструкция → загрузка PDF → обращение к специалисту → ответ администратора, плюс розыгрыш призов и полноценная админ-панель внутри Telegram (пользователи, рассылки, розыгрыши, контент, уведомления, статистика).

Стек: Python 3.12, aiogram 3, SQLAlchemy 2 (async), PostgreSQL, Alembic, Redis (FSM + планировщик), APScheduler, Docker.

## 1. Быстрый старт (Docker, рекомендуется)

1. Скопируйте `.env.example` в `.env` и заполните значения (см. раздел «Переменные окружения» ниже).
2. Соберите и запустите контейнеры:

   ```bash
   docker compose up -d --build
   ```

   Контейнер `bot` при старте автоматически выполнит `alembic upgrade head`, затем запустит бота (см. `entrypoint.sh`).

3. Логи:

   ```bash
   docker compose logs -f bot
   ```

## 2. Настройка Telegram

### 2.1. Создание бота

1. Напишите [@BotFather](https://t.me/BotFather), выполните `/newbot`, получите токен → `BOT_TOKEN`.
2. Отключите Privacy Mode (`/setprivacy` → Disable), если бот должен видеть все сообщения в группах (для личных чатов не требуется).

### 2.2. Канал для обязательной подписки

1. Создайте приватный или публичный канал («Страх Банкира» или любое другое название).
2. Добавьте бота в канал **администратором** (без этого `getChatMember` не будет работать для приватных каналов, а в публичных — нужен как минимум доступ на чтение состава для приватных).
3. Узнайте числовой ID канала (например, через [@userinfobot](https://t.me/userinfobot) переслав туда сообщение из канала, либо через `getUpdates`). ID выглядит как `-100XXXXXXXXXX`.
4. Заполните `REQUIRED_CHANNEL_ID`, `REQUIRED_CHANNEL_URL`, `REQUIRED_CHANNEL_NAME` в `.env`.

Название канала и ссылку впоследствии можно менять прямо из админки (раздел **Настройки**) без передеплоя.

### 2.3. Администраторы

Укажите Telegram ID администраторов через запятую в `ADMIN_IDS` (узнать свой ID можно у [@userinfobot](https://t.me/userinfobot)). Доступ к `/admin` есть только у пользователей из этого списка.

Опционально можно включить дополнительный код доступа: заполните `ADMIN_SECRET_KEY` — тогда при первом входе в сессии бот запросит код перед показом меню админки. Если оставить пустым — код не запрашивается.

## 3. Переменные окружения

Полный список — в `.env.example`. Ключевые:

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен бота от BotFather |
| `DATABASE_URL` | Строка подключения к Postgres (asyncpg) |
| `DATABASE_URL_SYNC` | Та же БД, но с sync-драйвером (для Alembic) |
| `REDIS_URL` | Redis для FSM-хранилища и очереди APScheduler |
| `ADMIN_IDS` | Telegram ID администраторов через запятую |
| `ADMIN_SECRET_KEY` | Необязательный код доступа в админку |
| `REQUIRED_CHANNEL_ID` / `_URL` / `_NAME` | Канал обязательной подписки |
| `SPECIALIST_CHAT_ID` | Доп. чат, куда также дублируются уведомления (необязательно) |
| `GIVEAWAY_POST_URL` | Ссылка на пост для условия розыгрыша |
| `REMINDER_DELAY_SECONDS` | Через сколько секунд слать повторные напоминания |
| `MAX_REMINDERS` | Максимум повторных напоминаний одному адресату |
| `MAX_FILE_SIZE_MB` | Лимит размера загружаемого пользователем PDF |

`REQUIRED_CHANNEL_URL`, `REQUIRED_CHANNEL_NAME`, `GIVEAWAY_POST_URL`, `SPECIALIST_CHAT_ID` — это лишь **стартовые значения**: после первого запуска они переезжают в таблицу `content` и редактируются через админку (**Настройки**) без перезапуска бота.

## 4. Локальный запуск без Docker

```bash
python3.12 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# Поднимите Postgres и Redis самостоятельно (или через docker compose up -d postgres redis)
cp .env.example .env  # заполните значения

alembic upgrade head
python main.py
```

## 5. Миграции

Все изменения схемы — только через Alembic:

```bash
alembic revision --autogenerate -m "описание изменения"
alembic upgrade head
```

Откат последней миграции: `alembic downgrade -1`.

## 6. Архитектура проекта

```
app/
  config.py              # Settings (pydantic-settings) из .env
  bot/                    # Пользовательский флоу
    handlers/             # /start, подписка, инструкция, PDF, специалист, розыгрыш
    keyboards/            # Inline-клавиатуры
    states/                # FSM пользователя (обращение к специалисту)
    middlewares/           # DB-сессия, активность пользователя, троттлинг
    filters/                # IsAdminFilter
  admin/                  # Админ-панель (доступна только ADMIN_IDS)
    handlers/              # Меню, пользователи, рассылки, розыгрыши, уведомления,
                            # статистика, контент/настройки
    states/                 # FSM админки (рассылка, ответ, поиск, контент, розыгрыш)
    keyboards/
  database/
    models/                 # SQLAlchemy-модели (15 таблиц)
    repositories/           # Репозитории поверх моделей
    session.py, base.py
  services/                # Вся бизнес-логика: users, subscriptions, files,
                            # specialist, giveaway, mailings, notifications,
                            # statistics, tags, content, scheduler, calculation
  utils/                    # Логирование, callback_data, форматирование
migrations/                 # Alembic
tests/                      # pytest (32 теста, aiosqlite)
main.py                     # Точка входа: сборка Dispatcher, middlewares, scheduler
```

Бизнес-логика находится только в `services/`; хендлеры вызывают сервисы и рендерят клавиатуры.

## 7. Расчёт потенциальной переплаты

`app/services/calculation.py` — при загрузке PDF-выписки бот скачивает файл, извлекает из него текст (`pdfplumber`) и ищет строки, содержащие ключевое слово (по умолчанию **«страх»** — покрывает «страхование», «страховка» и т.п.). Сумма модулей всех найденных в этих строках платежей и есть переплата, которую показываем пользователю и администратору.

Ключевое слово редактируется в админке (**Настройки → setting_calculation_keyword**) или через `.env` (`CALCULATION_KEYWORD`) без правки кода.

Если в файле не нашлось ни одной строки с ключевым словом (другой формат выписки, отсканированный документ без текстового слоя, повреждённый файл) — метод возвращает `None`, и UI корректно показывает «сумма пока не определена» + кнопку «Написать специалисту», чтобы специалист посчитал вручную.

## 8. Резервное копирование БД

```bash
# Бэкап
docker compose exec postgres pg_dump -U bot bot > backup_$(date +%Y%m%d_%H%M%S).sql

# Восстановление
cat backup_20260101_120000.sql | docker compose exec -T postgres psql -U bot -d bot
```

Рекомендуется поставить это на cron/systemd-timer на проде.

## 9. Продакшн-деплой на VPS

1. Установите Docker + Docker Compose на сервере.
2. Склонируйте репозиторий, заполните `.env` реальными значениями (боевой токен, боевой канал, ID реальных админов).
3. `docker compose up -d --build`.
4. Контейнеры настроены с `restart: unless-stopped` — переживут перезагрузку сервера.
5. Healthcheck у Postgres и Redis гарантирует, что бот стартует только после готовности зависимостей.
6. Логи бота пишутся в `./logs` (смонтировано в `docker-compose.yml`).
7. Настройте регулярный бэкап БД (см. п.8) и мониторинг контейнеров (например, `docker compose ps`, `docker stats`).

## 10. Тесты

```bash
pip install -r requirements.txt
pytest -v
```

Тесты используют in-memory SQLite и не требуют поднятой инфраструктуры. Покрывают: регистрацию пользователей, проверку подписки, участие в розыгрыше и защиту от повторного участия, приём PDF, создание заявок, авторизацию администратора, ответ администратора, создание/отмену/планирование рассылок, фильтрацию аудитории по тегам.
